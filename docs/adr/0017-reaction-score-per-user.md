# ADR-0017: 반응 점수를 유저 단위로 두고 프롬프트에 숫자를 넣지 않기

## 상태

Accepted

## 맥락

캐릭터가 쓴 수에 유저가 어떻게 반응했는지는 관계 표의 잘 통하는 것 한 항목에 글로만 남고, 그 글은 새벽 정리가 어제 대화의 인상으로 다시 쓰기 때문에 어떤 수가 통하는지가 쌓이지 않는다. 캐릭터를 끝내고 새로 만들면 그 인상도 같이 사라진다. 그렇다고 점수 숫자를 프롬프트에 넣으면 모델이 점수를 말하거나 점수를 올리려는 티를 내고, 표본이 2~3개일 때 값을 과신한다.

## 결정

- 반응 점수는 유저 대화방과 수 코드를 키로 둔다. 캐릭터를 바꿔도 점수가 이어진다.
- 계산은 코드가 새벽 정리의 수집 단계에서 한다. 답장 속도·길이·웃음 표기·되묻기·이어진 턴 수·상대 상태·판정 호출의 수 반응 7개를 유저의 최근 14일 중앙값과 견줘 −1·0·+1로 매기고 가중합한 값을 지수 이동 평균으로 갱신한다. 초기값은 0이다.
- 점수 숫자는 어느 프롬프트에도 넣지 않는다. 새벽 정리는 점수 순으로 늘어놓은 시도할 수 추천 목록과 잘 통하는 수 이름 목록만 받고, 모델이 잘 통하는 것 항목에 말로 옮긴다.
- 5일에 하루는 표본이 가장 적은 수를 추천 목록 맨 앞에 두어 새 수를 시험한다.

계산식과 값은 relationship.md 6절에 있다.

## 대안

- 캐릭터 단위로 둔다. 캐릭터를 바꾸면 처음부터 다시 배워야 해서 버렸다.
- 모델이 어제 대화를 읽고 점수를 매긴다. 날마다 기준이 흔들리고 호출이 늘어 버렸다.
- 숫자를 프롬프트에 넣는다. 모델이 점수를 언급하거나 최적화하려는 티를 내서 버렸다.
- 학습 없이 고정 순서로 수를 쓴다. 유저마다 다른 취향을 반영하지 못해 버렸다.

## 결과

- 유저가 한 명일 때는 표본이 적어 첫 2주의 점수를 믿기 어렵다. 표본 3개 미만인 수는 잘 통하는 것에 옮기지 않는다.
- 가중치와 문턱은 첫 값이며, 구현 6이 2주 동안 본 뒤 조정한다.
