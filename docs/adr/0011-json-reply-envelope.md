# ADR-0011: 답장 본문과 신호를 JSON 한 덩이로 받기

## 상태

Accepted

## 맥락

모델이 코드에 신호를 넘기는 통로는 답장에 붙이는 대괄호 표시였다. 자기 일정을 취소하거나 미루고 상대 곁에 남기로 하면 답 맨 앞에 `[남음]`을, 기억해 둘 사실이 나오면 맨 끝 줄에 `[메모]`를 붙이게 하고, 코드가 그 표시를 떼어내 값으로 읽었다.

표시가 유저에게 나가는 문장과 같은 문자열 안에 있어서, 떼어내기가 한 번 어긋나면 그대로 상대에게 보인다. 표시가 겹쳐 나올 때 하나만 벗기고 나머지를 문장으로 내보내던 문제가 실제로 있었다(이슈 #7). 모델이 대화 기록의 시간 마커를 흉내 내 답장 앞에 찍는 경우까지 덮느라 대괄호 안 길이를 20자로 제한하는 조건도 붙어 있었다. 신호를 하나 더할 때마다 떼어내는 규칙이 하나씩 늘어나는 구조라, 관계 단계와 호칭을 같은 통로로 받는 작업(이슈 #144)과 신호를 붙이는 조건을 넓히는 작업(이슈 #145)을 앞두고 통로부터 바꾸기로 했다.

## 결정

답장 본문과 신호를 JSON 객체 하나로 받는다. 본문은 `reply` 배열에만 담고 신호는 그와 나란한 다른 키에 담아서, 읽기가 실패해도 신호가 유저에게 보이는 문장에 섞여 들어가지 않는다. 말풍선을 나누는 자리도 줄바꿈에서 배열 원소로 옮겼다.

- 형식을 시키는 프롬프트와 그 형식을 읽는 코드를 한 파일(`src/reply-signal.ts`)에 둔다. 시키는 모양과 기다리는 모양이 따로 놀면 답장이 통째로 사라지므로, 둘을 같이 고치게 강제한다.
- 형식 블록은 답장 경로에서만 프롬프트 맨 끝에 붙인다. 선제 연락 문안 여섯 곳은 같은 3층 프롬프트를 쓰되 자기 형식으로 답하기 때문에, 공통 규칙층에 넣으면 두 형식이 부딪힌다.
- 읽는 순서는 넷이다. JSON으로 읽히면 그대로 쓰고, 상한에 걸려 잘린 답이면 온전히 닫힌 조각만 건지고, 형식을 아예 안 쓴 답이면 옛 방식대로 줄바꿈으로 나눠 내보내고, 아무것도 못 건지면 한 번 다시 부른 뒤 그래도 비면 보내지 않는다.
- 형식을 쓰려던 흔적이 있는 답은 읽지 못해도 원문을 내보내지 않는다. JSON 조각이 그대로 말풍선이 되면 옛 문제의 재판이다.
- 신호를 늘릴 때 고칠 자리를 한 파일 안 네 곳으로 모았다. 신호 목록, 프롬프트 설명 한 줄, 값 읽기, 두 답 합치기다.

## 대안

**도구 호출(tool calling).** 모델이 신호를 도구 인자로 넘기면 형식을 코드가 강제할 수 있다. 다만 모델이 도구를 부르는 턴에서 답장이 짧아지거나 아예 빠지는 일이 있어, 대화 자체가 얇아질 위험을 먼저 확인해야 한다. JSON으로 문체가 딱딱해지는 것은 프롬프트로 고칠 수 있다고 판단해 JSON을 먼저 해보기로 하고, 도구 호출은 이 방식의 결과를 보고 다시 판단한다.

**대괄호 표시를 그대로 두고 떼어내는 규칙만 늘리기.** 바꾸지 않아도 지금은 돌아가지만, 신호가 늘수록 규칙이 같이 늘고 새어 나갈 자리도 늘어난다. 앞으로 얹을 신호가 이미 둘이라 택하지 않았다.

## 결과

신호가 유저에게 보일 위험이 구조적으로 사라진다. 신호를 늘릴 때 프롬프트 한 줄과 값 읽기 한 줄만 더하면 되고, 잘린 답에서 건지는 자리는 값 읽기를 그대로 쓰므로 손대지 않아도 된다. 답을 어느 길로 읽었는지 트레이스에 남겨서, 형식이 운영에서 얼마나 지켜지는지 슬랙 채널에서 확인할 수 있다.

감수하는 것은 셋이다. 형식 설명 몇 줄이 프롬프트 꼬리에 늘고, 이 자리는 매번 바뀌는 층이라 캐시를 타지 않는다. JSON 키와 따옴표가 본문 밖에서 토큰을 쓰고 답이 잘리면 한 덩이가 통째로 못 쓰게 되므로, 답장 출력 상한을 1024에서 1200으로 올렸다. 그리고 형식을 지키느라 문체가 굳을 수 있어서, 실제 답장을 보고 프롬프트로 다듬어야 한다.

되돌리려면 `src/reply-signal.ts`를 지우고 `bot.ts`의 답장 두 자리를 옛 방식으로 돌린 뒤, `context.ts`의 규칙 두 곳(오늘 메모·유저가 붙잡을 때)을 대괄호 표현으로 되돌리면 된다. 답장 트레이스의 형식 표시도 함께 뺀다.
