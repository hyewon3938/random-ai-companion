# ADR-0013: 코드를 영역 7개로 나눠 표로 관리하기

## 상태

Accepted

## 맥락

`src/` 아래 파일 32개와 도구 21개가 한 폴더에 평평하게 놓여 있고, 그중 bot.ts·nightly.ts·db.ts·reply-trace.ts는 1,000줄에서 2,500줄이다. 어떤 변경이 어느 파일에 닿는지는 파일을 열어 봐야 알 수 있어서 세션마다 같은 정찰을 되풀이했고, 리팩토링을 시작하려면 먼저 어디를 어떤 단위로 나눌지 합의된 지도가 필요했다.

기존 문서는 축이 다르다. modules.md는 봇 프로세스와 새벽 배치라는 실행 시점 순으로, erd.md는 표 단위로, CLAUDE.md의 색인은 알파벳순 파일 목록으로 되어 있어서, 셋 다 어떤 변경이 어느 묶음에 속하는지는 답하지 않는다.

## 결정

파일을 같이 바뀌는 정도와 import 방향을 근거로 영역 7개로 묶고, 영역 표를 루트의 areas.md에 둔다. 근거로 쓴 것은 2026-08-01 이후 커밋에서 파일 쌍이 같이 바뀐 횟수, 파일끼리 import하는 방향, 그리고 파일 하나 안에서 책임이 갈리는 자리다.

영역은 1 기반과 저장, 2 기억, 3 캐릭터의 삶, 4 대화 생성, 5 실행과 발송, 6 새벽 정리, 7 관측과 운영이다. 번호가 큰 영역이 작은 영역을 쓰고 반대 방향 import는 만들지 않는다. 7번은 모든 영역에 걸치는 예외이고, index.ts는 시작점이라 규칙 밖이다. reply-timing과 proactive-policy는 보낼지와 언제 보낼지를 정하는 판단이라 4번에 두어, 5번과 6번이 서로 import하지 않게 했다.

영역은 폴더가 아니라 표로만 존재한다. 파일은 옮기지 않고, 분해 작업으로 새 파일이 생길 때 그 영역 이름의 폴더를 만든다. `scripts/gen-modules.mjs`가 표를 읽어 파일 색인을 영역별로 areas.md에 쓰고 같은 표를 CLAUDE.md에 옮겨 적으며, 표에 없는 src 파일이 있으면 커밋 훅이 막는다. CLAUDE.md에는 영역 표만 두고 파일별 한 줄 색인은 areas.md로 옮긴다.

## 대안

- 폴더로 물리 분리. 파일 32개를 지금 옮기면 import 경로가 한꺼번에 바뀌어 진행 중인 기능 브랜치와 충돌하고, 옮긴 뒤에도 bot.ts의 답장 파이프라인이나 nightly.ts의 문안과 아크처럼 파일 안에서 갈리는 책임은 그대로 남는다. 분해와 함께 옮기는 편이 한 번에 끝난다.
- 영역 5개. 기억을 기반에, 새벽 정리를 실행에 합치면 5개가 되지만, 기억은 2번·4번·6번이 같이 읽는 경계라 따로 두어야 검색 정책 변경이 어디로 가는지 분명하고, 새벽 정리는 봇 밖 실행 경로가 있어 실행과 배포 단위가 다르다.
- 실행 시점 축만 유지. modules.md만으로는 일정 시각을 고칠 때 볼 곳으로 3번·4번·6번 셋을 답해야 해서 변경 단위와 맞지 않는다.

## 결과

변경이 어느 영역인지 표에서 바로 나오고, 리팩토링을 영역 단위 이슈로 잘라 한 번에 하나씩 진행할 수 있다. 새 파일은 표에 넣어야 커밋되므로 지도가 코드와 같은 커밋에서 움직인다. CLAUDE.md는 파일별 색인이 빠져 세션마다 들어가는 글자 수가 줄어든다.

감수하는 것은 폴더 구조가 지도와 다르다는 점이다. 의존 방향 규칙은 검사로 강제하지 않고 문서 규칙으로 두며, 지금 어긋난 선 1개인 character.ts에서 nightly.ts로 가는 import는 리팩토링 1단계에서 지운다. 되돌리려면 areas.md와 gen-modules.mjs의 표 읽기를 지우고 CLAUDE.md 색인을 파일 목록으로 되돌리면 된다.
